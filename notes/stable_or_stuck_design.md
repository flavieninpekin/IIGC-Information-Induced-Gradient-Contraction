# 可操作的 Stable-or-Stuck 诊断（设计）

> 目标：把上一篇的 Stable-or-Stuck 从**描述性 2×2 表**升级为
> **可运行、有样本量保证、经干预验证**的诊断工具。
> 用我们验证过的分解（P1-P4 + N* 定理）落实。
> 状态：设计稿（用户需评审）。

---

## 1. 上一篇的问题（为什么不够 practical）

上一篇的诊断规则：
```
能量门 E：E≈0 → N/A
低P/高κ → 收敛；低P/低κ → 收缩停滞；高P/高κ → 协同运动；高P/低κ → 冲突
```
局限：
1. **κ 尺度失明**（P4）：弱信号 run 的 κ 也可以很高 → "高κ=收敛"可能误判
2. **κ 噪声混合**：混合协议下单集噪声淹没信号 → 测不准
3. **无阈值、无样本量指导**：审稿人问"多少数据才能信这个判断？"
4. **未验证"诊断→干预→好转"闭环**

## 2. 升级后的工作流（practitioner 跑什么）

输入：checkpoint + env + mode。输出：STUCK / CONVERGED / N-A + 置信度 + 所需样本量。

```
① 强制分配 rollout（固定关系 per rollout）
② 计算 E_shared, E_contrast, σ², E_total；能量门 + 全方差守恒检验
③ 决策规则（见下）
④ 用 N* 定理报告"这个判断需要 N 个 episode、置信度多少"
```

## 3. 决策规则（修正：能量门 × κ，无新判据）

> 修正说明（2026-08-01）：早期草稿提"用 E_shared≈0 代替低 κ"是错的——
> E_shared/(E_shared+E_contrast) 本身就是 κ；且绝对 E_shared≈0 依赖 reward
> 缩放（P4 反向问题），会把弱信号健康 run 误判为卡死。
> 正确结构是**原来的"能量门 × κ"，升级在于测量可靠性，不在判据**。

| 判定 | 判据 | 谁负责尺度 |
|------|------|-----------|
| **N/A** | E_total ≈ 0（能量门） | 门（尺度感知）|
| **STUCK** | E_total ≫ 0 且 κ ≈ 0（健康能量但全抵消） | 门+κ |
| **LEARNING** | E_total ≫ 0 且 κ 高 | 门+κ |
| **CONVERGED** | E_total ≈ 0 且 reward 好（需 reward 定夺，纯梯度无法区分收敛与无信号） | 门+reward |

- κ（尺度不变）管保留比例——无法用别的比值替代
- 能量门管"信号到底多强"——P4 的"κ 高但 E_total 小 = 弱信号别信"由门兜住
- **分解的真正贡献 = 可靠测量**：强制分配给出可信的 E_total 与 κ
  （510K 混合协议下 κ 平坦不可信）、N* 保证样本量、守恒检验保证可信

路径积分 P 保留为行为侧检查（策略还在动吗）。

## 4. 样本量协议（N* 定理落地）

- **比较/排序多个 run**：对每对算 N*，取 N > max N* 保证排序可靠
  （定理已验证：合成反例 N*=99 精确命中）
- **单点诊断**（判断 E_shared≈0）：用收敛曲线，N≈50-100 eps/partner
  → κ ±0.01；分量 bootstrap ~18%
- 报告形如："该判定基于 N=80 episodes/partner，κ=0.03±0.01，
  与全样本（真值 κ=0.05）无显著差异"

## 5. 验证设计：510K stuck 检测（核心实验）

### 5.1 受控 ground truth
- **stuck-prone**：DYNAMIC（隐藏队友）→ 假设信息卡死
- **converged**：OBVIOUS（队友可见）→ 假设真收敛
- 辅助条件：reveal-trained 模型（p=0 vs p=1）已有 126 个

### 5.2 细 checkpoint（关键修正）
之前 forecaster 失败在粗 checkpoint（100K）——SAC 100K 内已收敛、无轨迹可测。
新训练用 **10-20K 细 checkpoint**，捕捉收敛/卡死过程。

### 5.3 干预验证闭环（诊断的 practical 价值）
```
1. DYNAMIC 训到 checkpoint t → 分解诊断 → STUCK（E_shared≈0）
2. 干预：加可见队友信息（OBVIOUS / 加传感器）继续训
3. 验证：E_shared↑、κ↑、reward↑  ← 诊断预测的修复真的有效
4. 对照：不干预的 run 保持 STUCK
```
这是"测 κ → 诊断 → 干预 → 用 κ 验证修复"闭环的定量版
（上一篇 case study 只是示意）。

### 5.4 基线对比（同一任务）
reward 平坦度 / 路径积分（上一篇）/ 原始 κ / 梯度范数 / PCGrad 式梯度冲突
——κ+分解必须**更早、更准**检测 STUCK。

### 5.5 指标
- 检测提前量（多少步前 flag STUCK vs reward/基线）
- 分类准确率 / AUC（vs ground truth 标签）
- 干预后改善量

## 6. 诚实风险

1. **510K 混合协议对 κ 不灵敏**（已证）→ 必须用强制分配（受控红A发牌）
2. **forecaster 失败过** → 本设计是"分类当前状态 + 干预验证"，
   不是"预测未来 reward"；但需在报告里明确区分
3. **细 checkpoint 需新训练**（10-20K 粒度）→ 真实成本
4. **OBVIOUS vs DYNAMIC 是否真是 stuck/converged 对照组** → 需先用
   Toy 验证逻辑（HIDDEN=stuck、REVEALED=converged 已干净成立），
   再搬到 510K
